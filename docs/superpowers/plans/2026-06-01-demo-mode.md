# Demo Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `DEMO_MODE=true` flag to the existing codebase that, when deployed to Koyeb, turns IMMS into a fully interactive, resettable client demo at a custom subdomain — with a branded landing page, one-click role entry, in-app demo chrome, scripted seed data, and email capture instead of real sending.

**Architecture:** All demo behavior lives behind a single `DEMO_MODE` env var — no fork, no separate codebase. Backend gates 5 demo-only endpoints with a `requireDemoMode` middleware (404 in production). Frontend reads `REACT_APP_DEMO_MODE` at build time to render the landing page and demo chrome. A dedicated Postgres DB on Koyeb is wiped and reseeded by a single idempotent seed script, callable manually via the in-app Reset button or automatically at 3 AM via node-cron.

**Tech Stack:** Express/Node.js (existing), PostgreSQL (existing), React/TypeScript + MUI (existing), Framer Motion (new), Lucide React (new), node-cron (new), bcrypt (existing), jsonwebtoken (existing)

// backend/src/middleware/requireDemoMode.js
const requireDemoMode = (req, res, next) => {
  if (process.env.DEMO_MODE !== 'true') {
    return res.status(404).json({ message: 'Not found' });
  }
  next();
};

module.exports = requireDemoMode;
